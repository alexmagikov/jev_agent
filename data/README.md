# Датасеты диалогов

Все новые диалоги и реквизиты синтетические. Эталоны составлены вручную по общим
правилам проекта, до запуска моделей на новых примерах. Это набор регрессий и
сложных сценариев, а не репрезентативная выборка реальных обращений и не
доказательство преимущества Jev.

| Набор | Диалоги | Эталоны | Всего | dev / test |
| --- | --- | --- | ---: | ---: |
| Исходный | `cases.jsonl` | `labels.jsonl` | 41 | 28 / 13 |
| Расширенный v2 | `cases_v2.jsonl` | `labels_v2.jsonl` | 81 | 48 / 33 |

Первые 41 строки каждого файла v2 полностью сохраняют соответствующий исходный
файл, включая ID, порядок, разбиение и согласованную разметку. Исходные файлы не
меняются. Дополнение — ровно 40 кейсов `C042–C081`: 24 счёта, 10 переводов себе,
6 примеров `none`; из новых кейсов 20 относятся к dev, 20 к test.

У каждого диалога уникальные ID реплик. Все поля выбранного шаблона присутствуют
в эталоне; неизвестные значения явно `null`. `evidence` содержит только ID
сообщений пользователя. Разметка хранится отдельно и не передаётся моделям.
Неизвестность модели не трактуется как неоднозначность пользовательских данных.

Обычные описания позиций приводятся к единственному числу и именительному падежу,
когда это однозначно. Названия в кавычках и слова без единственного числа сохраняются.
Нормализация описания не меняет физическое количество, `subject` и цитаты.

Часть смысловых правил общая с первым набором, но новые диалоги не являются его
дословными копиями. Сводная оценка v2 включает старые примеры: её нельзя выдавать
за результат только на 40 новых или за независимый holdout после настройки на них.
Новые test-кейсы не используйте для подбора промптов и порогов. Прирост после
добавления Jev нужно измерять парно, учитывая ухудшения, ошибки API и полный бюджет.

## Запуск

Из корня `jev-agent`. Следующие команды выполняют реальные запросы к API;
они приведены для запуска пользователем, а не были выполнены при создании данных.
Для сравнения нужны одинаковые параметры моделей и разные выходные файлы.

```bash
uv run --locked python -m src.main --mode llm-only --input data/cases_v2.jsonl --labels data/labels_v2.jsonl --split all --output outputs/v2-llm-only.jsonl
uv run --locked python -m src.main --mode full --input data/cases_v2.jsonl --labels data/labels_v2.jsonl --split all --output outputs/v2-full.jsonl
```

Без новых параметров программа по-прежнему использует первый датасет.
Для настройки сначала используйте `--split dev`. Для парного аудита можно передать
те же `--input` и `--labels` в `scripts.audit_jev`; число и бюджет вызовов задаются
отдельно. Старые seed-trace из 41 кейса не содержат новых 40 исходных кандидатов.

## Воспроизводимость и проверка

Источник новых диалогов и ручных решений — `scripts/build_dataset_v2.py`.
Отсутствующие поля шаблона при сборке заполняются как missing; ответ модели здесь
не генерируется. JSONL-файлы v2 собираются скриптом, не редактируются вручную.
Изменения сценариев вносятся в источник; изменение первого набора также требует
повторной сборки v2. Это меняет версию данных, поэтому сохраняйте хеши при оценке.

```bash
# Пересобрать только файлы v2; оригиналы не перезаписываются, API не вызываются
uv run --locked python -m scripts.build_dataset_v2

# Только проверить соответствие файлов источнику
uv run --locked python -m scripts.build_dataset_v2 --check

# Проверить включение исходного набора, схемы, источники и ключевые решения
uv run --locked python -m pytest -q tests/test_dataset_v2.py
```
